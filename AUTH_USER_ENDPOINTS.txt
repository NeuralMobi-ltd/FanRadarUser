AUTH & USER ENDPOINTS SPEC
===========================

Base URL: {API_CONFIG.baseURL}
(Current dev fallback: http://localhost:3000)

AUTH
-----
1. POST /api/auth/login
   Purpose: Authenticate user and return token + user.
   Body (JSON): { email: string, password: string }
    Success 200:
       {
          "message": "Connexion réussie.",
          "token": "<token>",
          "user": {
             "id": 42,
             "username": "johnny",
             "first_name": "John",          // optional if using separate names
             "last_name": "Doe",            // optional
             "email": "john@example.com",
             "avatar": "https://cdn.example.com/avatars/42.png",
             "cover_photo": "https://cdn.example.com/covers/42.jpg",
             "bio": "Music + tech fan",
             "gender": "male",              // male|female|other|null
             "birth_date": "2002-05-17",    // YYYY-MM-DD or null
             "categories": ["Gaming","Music","Movies"], // or numeric IDs
             "isVerified": false,            // or verified
             "stats": {                      // optional aggregated counters
                "followers": 120,
                "following": 55,
                "posts": 18
             },
             "preferences": {                // optional future-proof area
                "language": "en",
                "theme": "dark"
             },
             "created_at": "2025-08-20T10:15:30Z",
             "updated_at": "2025-08-25T09:02:11Z"
          }
       }
   Errors: 401 invalid credentials.

2. POST /api/auth/register
   Purpose: Create a new user account (registration deferred until categories chosen).
   Body (JSON): {
     username?: string,
     first_name?: string,
     last_name?: string,
     email: string,
     password: string,
     password_confirmation: string (auto-filled same as password if omitted),
   gender?: string (male|female|other),
   birth_date?: string (ISO date YYYY-MM-DD),
     categories?: number[] | string[] (up to 5)
   }
    Success 201/200:
       {
          "message": "Inscription réussie.",
          "token": "<token>",
          "user": {
             "id": 43,
             "username": "sarah",
             "first_name": "Sarah",
             "last_name": "Lee",
             "email": "sarah@example.com",
             "avatar": null,
             "cover_photo": null,
             "bio": "",     
             "gender": "female",
             "birth_date": "2001-11-02",
             "categories": ["Gaming","Sports"],
             "isVerified": false,
             "stats": { "followers": 0, "following": 0, "posts": 0 },
             "created_at": "2025-08-28T12:00:05Z",
             "updated_at": "2025-08-28T12:00:05Z"
          }
       }
   Validation 422: { message, errors: { field: [..] } }

5. PUT /api/users/avatar  (Auth required, multipart/form-data)
   FormData: avatar (file) or profile_image (file) [choose one key]
   Success: { message: "Avatar updated.", user: { avatar: "url", ... } }

6. PUT /api/users/cover-photo  (Auth required, multipart/form-data)
   FormData: cover (file) or cover_image (file)
   Success: { message: "Cover updated.", user: { cover_photo: "url", ... } }

FOLLOW / SOCIAL (User related)
------------------------------
7. GET /api/users/{id}/posts
    Purpose: List public (or permitted) posts authored by user {id}.
    Query Params (optional):
       page (int, default 1) | per_page (int, default 10, max 50)
       sort=new|top|popular
       before / after (cursor or ISO datetime) for cursor pagination
    Success 200:
       {
          "data": [
             {
                "id": 987,
                "author_id": 42,
                "content": "Post text...",
                "media": [{ "type":"image","url":"https://..." }],
                "likes": 24,
                "comments": 5,
                "liked": false,          // current user liked?
                "saved": false,          // optional
                "created_at": "2025-08-28T10:34:11Z",
                "updated_at": "2025-08-28T10:34:11Z"
             }
          ],
          "pagination": { "page":1, "per_page":10, "total":56, "total_pages":6 }
          // or cursor form: { "next_cursor":"abc", "prev_cursor":null }
       }
    Errors: 404 user not found | 401/403 if private content.

8. GET /api/users/{id}/followers
    Purpose: List users who follow user {id}.
    Query Params: page, per_page, q (search), mutual_only=true (filter only mutuals).
    Success 200:
       {
          "data": [
             {
                "id": 55,
                "username": "alice",
                "avatar": "https://...",
                "isVerified": false,
                "bio": "Hi!",
                "followed_by_me": true,   // auth user follows Alice
                "follows_me": true,       // Alice follows auth user
                "mutual": true            // convenience flag (optional)
             }
          ],
          "pagination": { "page":1, "per_page":10, "total":120, "total_pages":12 }
       }
    Errors: 404 user not found.

9. GET /api/users/{id}/following
    Purpose: List users that user {id} is following.
    Query Params: page, per_page, q.
    Success 200 (structure mirrors followers):
       {
          "data": [
             {
                "id": 77,
                "username": "charles",
                "avatar": "https://...",
                "isVerified": true,
                "followed_by_me": false,  // auth user follows Charles?
                "follows_me": false,
                "mutual": false
             }
          ],
          "pagination": { "page":1, "per_page":10, "total":55, "total_pages":6 }
       }
    Errors: 404 user not found.

10. POST /api/users/{id}/follow
      Purpose: Toggle follow/unfollow user {id} (or explicit action model).
      Body (optional): { action: "follow" | "unfollow" }  // only if explicit model desired.
      Success 200 (toggle example - now following):
         {
            "message": "Followed user.",
            "following": true,
            "follower_count": 121,     // updated target follower count
            "following_count": 56      // updated auth user's following (optional)
         }
      Success 200 (unfollow):
         {
            "message": "Unfollowed user.",
            "following": false,
            "follower_count": 120
         }
      Errors:
         400 cannot follow yourself
         404 user not found
         409 already following (if using explicit follow action instead of toggle)
         401 unauthenticated

RELATIONSHIP FLAGS (for followers/following lists)
   followed_by_me : auth user follows that listed user
   follows_me     : listed user follows auth user
   mutual         : followed_by_me && follows_me (optional convenience)

RATE LIMIT SUGGESTIONS
   GET lists: 60 requests/min per IP
   POST follow: 30 requests/min per IP (prevents abuse / mass follow bots)

CLIENT NOTES
   - Optimistic UI: update button state & counts immediately after POST then reconcile if error
   - Consider ETag + If-None-Match for followers/following caching
   - Keep denormalized follower_count/following_count columns for O(1) updates


NOTES
-----
- categories[] is sent only at registration (or later via profile update) and limited to 5 by UI.
- password_confirmation automatically added client-side if missing.
- All update endpoints require Bearer token.
- File uploads must use multipart/form-data; backend should validate size & mime.
- Consistent user object fields recommended: id, username, email, first_name?, last_name?, avatar, cover_photo, bio, gender, birth_date, categories (array of names or IDs), isVerified/verified, stats {followers,following,posts}, preferences {..}, created_at, updated_at.

USER OBJECT FIELD DEFINITIONS
----------------------------
id (number)            Unique user ID.
username (string)      Public handle (unique).
first_name/last_name   Personal names (optional if username only).
email (string)         Unique email.
avatar (string|null)   Absolute or relative URL to avatar image.
cover_photo (string|null) Cover/banner image URL.
bio (string)           Short profile text (<=500 chars recommended).
gender (string|null)   male|female|other or null.
birth_date (string|null) ISO date YYYY-MM-DD.
categories (array)     User interest categories (names or IDs, max 5 in current UI).
isVerified/verified (boolean) Account verification flag.
stats (object)         { followers:number, following:number, posts:number }.
preferences (object)   Optional user preference bag (theme, language, etc.).
created_at/updated_at (ISO datetime strings) Auditing timestamps.

ERROR FORMAT (Suggested)
------------------------
401: { "message": "Unauthenticated." }
422: { "message": "The given data was invalid.", "errors": { field: ["msg"] } }

RATE LIMIT (Optional)
---------------------
- Consider 60 req/min per IP for auth endpoints.
